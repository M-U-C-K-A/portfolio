Le mode sombre n'est plus une "option sympa", c'est une attente de base. Mais mal l'implémenter peut nuire à l'expérience utilisateur, notamment avec le fameux **FOUC** (*Flash of Unstyled Content*) : ce flash blanc violent qui survient pendant quelques millisecondes avant que le JavaScript ne détecte vos préférences.

En 2026, nous avons des outils natifs pour régler ça proprement.

---

## 1. La fondation : `color-scheme`

Avant même d'écrire votre première variable CSS, vous devez informer le navigateur que votre site supporte les deux modes. Cela permet au navigateur d'adapter les éléments natifs (barres de défilement, boutons par défaut, formulaires).

```css
:root {
  /* Indique au navigateur que le site supporte les deux modes */
  color-scheme: light dark;
}

```

Cette simple ligne change la donne : si l'utilisateur est en mode sombre, le fond de page par défaut devient noir et le texte blanc, même avant que votre CSS ne soit totalement chargé.

---

## 2. La révolution : La fonction `light-dark()`

Oubliez les sélecteurs complexes `.dark-mode` à rallonge. Le CSS moderne nous offre la fonction `light-dark(valeur-claire, valeur-sombre)`.

```css
:root {
  --bg-color: light-dark(#ffffff, #0f172a);
  --text-color: light-dark(#1e293b, #f8fafc);
  --accent: #3b82f6;
}

body {
  background-color: var(--bg-color);
  color: var(--text-color);
}

```

Le navigateur choisit automatiquement la bonne valeur en fonction de la propriété `color-scheme` de l'élément. C'est propre, lisible et ultra-performant.

---

## 3. Éviter le "Flash Blanc" dans Next.js

Le problème du flash survient quand le serveur rend du HTML "neutre" (blanc) et que le client doit attendre le chargement du JS pour appliquer la classe `.dark`.

### La solution 2026 : Le script bloquant critique

La méthode la plus fiable reste d'injecter un petit script inline dans le `<head>` de votre fichier `layout.tsx`. Ce script s'exécute **avant** que le reste de la page ne soit dessiné.

```tsx
// Dans votre RootLayout
<head>
  <script
    dangerouslySetInnerHTML={{
      __html: `
        try {
          if (localStorage.theme === 'dark' || (!('theme' in localStorage) && window.matchMedia('(prefers-color-scheme: dark)').matches)) {
            document.documentElement.classList.add('dark')
          } else {
            document.documentElement.classList.remove('dark')
          }
        } catch (_) {}
      `,
    }}
  />
</head>

```

Grâce aux **Server Components** de Next.js, ce script est envoyé tel quel dans le HTML initial, garantissant une transition invisible.

## 4. Accessibilité et Mode Sombre

Le mode sombre n'est pas qu'une question d'esthétique, c'est aussi une question de confort visuel.

* **Contrastes :** Vérifiez que vos contrastes restent conformes aux normes WCAG en mode sombre. Parfois, un bleu qui passe bien sur blanc devient illisible sur un fond gris foncé.
* **Images :** Pensez à réduire légèrement la luminosité des images trop claires en mode sombre pour ne pas éblouir l'utilisateur.

```css
.dark img {
  filter: brightness(0.8) contrast(1.1);
}

```
