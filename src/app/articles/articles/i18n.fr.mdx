Traduire un site ne se résume pas à remplacer "Bonjour" par "Hello". C'est un défi d'architecture qui impacte le routage, le SEO, la performance et surtout l'expérience développeur.

En 2026, avec l'App Router de Next.js, l'internationalisation (i18n) est devenue plus structurée, mais demande une configuration rigoureuse pour rester performante.

---

## 1. Le Routage : Pourquoi `/fr` est indispensable ?

Il existe plusieurs façons de gérer la langue (cookies, local storage, headers). Cependant, pour le SEO, la structure d'URL est la seule méthode viable.

* **Sous-chemins (Recommandé) :** `monsite.com/fr` ou `monsite.com/en`.
* **Domaines :** `monsite.fr` ou `monsite.com`.

L'utilisation du sous-chemin permet aux moteurs de recherche d'indexer chaque version de votre page indépendamment. Next.js facilite cela grâce au **Middleware**, qui intercepte la requête, détecte la langue du navigateur et redirige l'utilisateur vers le bon préfixe si nécessaire.

---

## 2. Le Middleware : Le Chef d'Orchestre (Exemple Concret)

C'est ici que la magie opère. Le middleware intercepte chaque requête pour diriger l'utilisateur vers la bonne langue.

```typescript
import createMiddleware from 'next-intl/middleware';

export default createMiddleware({
  // Une liste de toutes les locales supportées
  locales: ['en', 'fr'],

  // Si aucune locale ne matche, on utilise celle-ci
  defaultLocale: 'fr',

  // Redirige / vers /fr
  localePrefix: 'always'
});

export const config = {
  // Match uniquement les pages internationalisées
  matcher: ['/', '/(fr|en)/:path*']
};
```

Cette simple configuration gère automatiquement la détection de la langue du navigateur et les redirections 307.

## 2. Organisation des dictionnaires : Le Typage d'abord

L'erreur classique est d'utiliser des objets JSON simples sans protection. En tant que développeur full-stack, vous voulez que TypeScript vous engueule si vous oubliez une clé de traduction dans une langue.

### La structure recommandée
```text
messages/
  en.json
  fr.json

```

### Typage strict des traductions

En utilisant des bibliothèques comme `next-intl` ou `i18next`, vous pouvez lier vos fichiers JSON à vos types :

```typescript
// Exemple de composant typé
import { useTranslations } from 'next-intl';

export function LoginButton() {
  const t = useTranslations('Auth');

  // TypeScript validera que 'login_label' existe bien dans fr.json et en.json
  return <button>{t('login_label')}</button>;
}

```

## 3. SEO et Accessibilité : Les oubliés de l'i18n

Traduire l'interface c'est bien, mais il ne faut pas oublier les métadonnées techniques.

1. **L'attribut `lang` :** Votre balise `<html lang="fr">` doit changer dynamiquement. C'est crucial pour les lecteurs d'écran (Accessibilité) afin qu'ils utilisent la bonne synthèse vocale.
2. **Les balises `hreflang` :** Elles indiquent à Google la relation entre vos pages. Si je suis sur la page "À propos" en français, la balise `hreflang` doit pointer vers la version "About" en anglais.

---

## 4. Dates, Chiffres et Currencies : L'API Intl

Ne traduisez jamais manuellement les dates ou les devises. Le navigateur et Node.js possèdent une API native ultra-puissante : `Intl`.

```javascript
const price = 1250.50;
new Intl.NumberFormat('fr-FR', { style: 'currency', currency: 'EUR' }).format(price);
// Résultat : 1 250,50 €

new Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' }).format(price);
// Résultat : $1,250.50

```

## 5. Comparatif des solutions en 2026

| Librairie | Avantages | Inconvénients |
| --- | --- | --- |
| **next-intl** | Conçu pour l'App Router, ultra léger, excellent support des Server Components. | Configuration initiale un peu plus longue. |
| **i18next** | L'écosystème le plus vaste, plugins pour tout (backend, mobile). | Plus lourd, parfois complexe avec les Server Components. |
| **FormatJS** | Standardisé, très robuste pour les très gros projets. | Plus verbeux. |

## 3. SEO International : Le Diable est dans les Détails

Avoir un `/fr` et un `/en` ne suffit pas. Google doit comprendre le lien entre eux.

### Balises Hreflang & Canonicals
`next-sitemap` ou `next-seo` ne gèrent pas toujours ça parfaitement.
Assurez-vous que votre `<head>` contient :
```html
<link rel="alternate" hreflang="en" href="https://site.com/en/blog" />
<link rel="alternate" hreflang="fr" href="https://site.com/fr/blog" />
<link rel="alternate" hreflang="x-default" href="https://site.com/en/blog" />
```
Sans le `x-default`, Google peut ignorer vos pages pour les utilisateurs qui ne parlent ni FR ni EN.

### Images Localisées
C'est souvent oublié : montrez une capture d'écran de l'interface EN pour les anglais, et FR pour les français.
```tsx
const screenshot = locale === 'fr' ? '/img/app-fr.png' : '/img/app-en.png';
<Image src={screenshot} alt={t('screenshot_alt')} />
```
C'est ce genre de détail qui augmente votre taux de conversion de 15%.
