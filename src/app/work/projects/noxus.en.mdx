## Overview

Noxus breaks the traditional linearity of textbooks. The application is based on the principle that a gap in mathematics is often a problem of **missing dependency**: you can't understand exponents without mastering multiplication.

The interface is deliberately **sober and professional**, inspired by productivity tools like Obsidian, to put users in a serious learning posture, regardless of their age.

The project was born from a simple observation: existing educational applications treat mathematics in a linear way, as if each chapter were independent. However, mathematics is inherently **interconnected**. Understanding derivatives requires mastering limits, which themselves depend on the notion of function, etc.

---

## The Problem Solved

### Limitations of Traditional Learning

Traditional mathematics education suffers from several fundamental problems:

1. **Forced linearity**: School programs impose a rigid order that doesn't always match individual student needs.

2. **Accumulation of gaps**: When a concept isn't understood, students move on to the next without consolidating the basics. These gaps accumulate and become insurmountable barriers.

3. **Lack of big picture**: Students never see the "big picture" — how fractions connect to percentages, how algebra prepares for differential calculus.

4. **Demotivation**: Without understanding the "why" of what they're learning, motivation crumbles quickly.

### The Noxus Solution

Noxus addresses these problems by offering a **complete map of mathematical knowledge**. Each concept is a node, each prerequisite is a link. Users navigate freely through this graph, exploring connections and filling gaps in a targeted manner.

---

## Key Features

### 🕸️ The Knowledge Graph

The heart of the application is a **Node and Graph system**. This revolutionary approach visualizes the entire mathematics curriculum as an interconnected network of concepts.

- Each concept is a node with its own educational content.
- Links represent prerequisites and outcomes.
- Users visualize their progression path and can "trace back" to the source of a misunderstanding.
- Intuitive navigation by zooming and moving through the graph.
- Filtering by level (Elementary, Middle School, High School, University).
- Instant search across the entire graph.

The graph currently contains **over 400 nodes** covering the entire French curriculum, from elementary school to university level.

### 📚 Rich & Hybrid Modules

Courses are not just text. The rendering engine supports a variety of formats to make learning as effective as possible:

- **Markdown & LaTeX**: For impeccable mathematical formula rendering.
- **Integrated Media**: Explanatory videos, GIFs, interactive images.
- **Tables & References**: For structuring complex data.
- **Interactive Exercises**: MCQs, problems to solve, and self-assessment.
- **Commented Examples**: Detailed step-by-step solutions.
- **Cross-links**: Direct clickable references to related concepts.

Each module is structured progressively, from fundamental concepts to more advanced applications. The typical structure of a module includes:

1. **Introduction**: Context and motivation of the concept.
2. **Definitions**: Key concepts presented formally.
3. **Explanations**: Simplification and intuitions.
4. **Examples**: Concrete applications.
5. **Exercises**: Increasing difficulty.
6. **Going Further**: Links to advanced concepts.

### 🎯 Content Adaptability

While the main interface remains unified and elegant (fine theme management Dark/Light, contrasts), the **educational content** adapts to the target audience.

- An "Addition" module for first grade will use emojis 🍎 and fun examples.
- An "Inferential Statistics" module for university will remain academic.
- Explanations adapt to the learner's level.
- Vocabulary evolves with subject complexity.
- Exercises are calibrated for the intended level.

This adaptability allows Noxus to serve both a 7-year-old child and a preparatory school student. The interface remains the same, only the content changes.

### 🏆 Progression System

Noxus integrates a complete progression system to motivate learning:

- **XP and Levels**: Each completed module earns experience points.
- **Badges**: Rewards for achievements (consecutive day streaks, completing an entire level, etc.).
- **Detailed Statistics**: Time spent, modules completed, exercise success rate.
- **Personalized Goals**: Users can set weekly goals.

The gamification system is deliberately **sober and non-intrusive**. The goal is not to create addiction, but to provide positive feedback on progression.

## Educational Philosophy

### Learning by Understanding, Not Memorizing

Noxus is based on a strong conviction: mathematics is not learned by heart, it is **understood**. Each gap is a door to a prerequisite to consolidate.

The graph approach allows:

1. **Identifying gaps**: Rather than stumbling on a concept, users can explore its foundations.
2. **Building solid understanding**: By mastering each node before moving on to the next.
3. **Customizing the path**: Everyone progresses at their own pace, according to their strengths and weaknesses.
4. **Visualizing progress**: The graph becomes a map of acquired knowledge.
5. **Making connections**: Seeing how concepts articulate with each other.

### From Elementary to University

The content covers the entire French mathematics curriculum:

- **Elementary (Grades 1-5)**: Numeration, operations, basic geometry, measurements, simple problems.
- **Middle School (Grades 6-9)**: Algebra, fractions, functions, descriptive statistics, plane geometry.
- **High School (Grades 10-12)**: Analysis, sequences, probability, vector geometry, trigonometry.
- **University (Bachelor's)**: Real analysis, linear algebra, inferential statistics, differential calculus.

Each level is represented by a distinct color in the graph, allowing intuitive visual navigation.

### Autonomy as a Goal

The ultimate goal of Noxus is not for users to remain dependent on the application, but to develop skills for **autonomous learning**. The app provides:

- Reusable reasoning methods.
- The habit of looking for foundations when something isn't understood.
- The ability to make connections between concepts.

## Technical Challenges

### LaTeX Rendering on Mobile

One of the biggest challenges was achieving fluid and performant LaTeX rendering on mobile. Existing solutions were either too slow or incomplete.

**Tested and abandoned approaches:**
- **WebView**: Too slow, communication problems.
- **react-native-katex**: Inconsistent rendering, heavy dependency.
- **MathJax**: Too much JavaScript overhead.

**Our custom solution** uses an optimized parser that:
- Pre-compiles LaTeX expressions at build time when possible.
- Uses cache for recurring expressions (LRU cache of 500 entries).
- Optimizes SVG rendering for complex formulas.
- Supports inline and block rendering.
- Handles syntax errors gracefully.

The result: **60fps** rendering even on pages with 50+ formulas.

### Graph Performance

Displaying a graph of several hundred nodes fluidly required advanced optimizations:

- **Spatial Culling**: Only visible nodes are rendered.
- **Dynamic LOD**: Level of detail adapts to zoom.
- **Quadtree**: Data structure for efficient spatial queries.
- **Native Animation**: Transitions handled on native UI thread.
- **Incremental Layout**: Graph layout is calculated progressively.

These optimizations allow fluid navigation even with 400+ nodes and 800+ links.

### Offline-First Synchronization

Noxus works perfectly offline, which required robust architecture:

- **Local SQLite**: All progression is stored locally.
- **Sync Queue**: Modifications are queued for synchronization.
- **Conflict Resolution**: Handling conflicts in case of simultaneous modifications.
- **Delta Sync**: Only differences are synchronized.

## Content Architecture

### Module Structure

Each Noxus module follows a standardized JSON structure:

```json
{
  "id": "derivatives-intro",
  "title": "Introduction to Derivatives",
  "level": "highschool",
  "xp": 50,
  "prerequisites": ["limits-intuition", "functions-continuity"],
  "unlocks": ["derivatives-rules", "derivatives-applications"],
  "content": {
    "sections": [...],
    "exercises": [...],
    "references": [...]
  }
}
```

### Dependency Graph

The graph is modeled as a **DAG (Directed Acyclic Graph)**:
- Each node has prerequisites and outcomes.
- No cycles are allowed (impossible to return to a prerequisite).
- Validation algorithms guarantee graph integrity.
